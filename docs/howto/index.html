How-To

Practical guides for working with AMT files: build one, check it, and understand what the messages mean. Each guide starts from a small example you can copy.

Build an AMT file

What an AMT file consists of, a complete file to start from, and how to turn existing RDF into AMT with a SPARQL CONSTRUCT query.

Check an AMT file

Run the checks, read what they say, and fix it. Every message is explained with the IRI it names, what causes it and what to add.

Run it and look at the result

From nothing to a graph in your browser: clone the runner, where to put your file, which command to type, where the result appears.

The short version

  1. Declare concepts (ex:Coin a amt:Concept ; rdfs:label "Coin").
  2. Make every end of every edge a node (ex:c1 amt:instanceOf ex:Coin), including the things your edges point to.
  3. Write edges as a statement with rdf:subject, rdf:predicate, rdf:object and amt:weight.
  4. Check before you reason: python run_amt.py my.ttl --check-only.
  5. Run and open the graph: python run_amt.py my.ttl, then out\latest\my.html.

Which tool for which job

You want to…Use
try a file once, without installing anything but Python and gitamt-runner → python run_amt.py my.ttl
check a file quickly while you build itpython run_amt.py my.ttl --check-only (or amt-runner my.ttl --check-only with the engine installed)
run it inside your own Python projectpip install -e . from amt-engine, then from amt import load_amt, diagnose
look at the graph and the inferred edgesthe HTML file of a run, or the Explorer in your browser (step by step)

The two things called amt-runner: the repository amt-runner is a small wrapper (run_amt.py) that fetches the engine for you; the engine itself also has a command amt-runner. Both accept the same options.
